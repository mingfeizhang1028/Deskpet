# 芽砚 Godot 桌宠：交互、漫游与视觉校准计划

## 1. 已确认目标

- 保持 `pet_renderer=godot`、Python 大脑、聊天/任务/专注/设置四个面板和启动/退出链路不变。
- 启动时桌宠默认位于当前屏幕右下安全区域。
- 用户拖动的是猫本体；透明 Godot 窗口在后台跟随猫移动。拖动到左上后，活动范围随窗口迁移到左上这一块。
- 拖动后的宠物窗口位置跨重启保存；显示器或分辨率变化时自动钳制到当前屏幕可用区域。
- 所有情绪状态的动画都做保持比例的视觉校准，减少逐帧忽大忽小、上下跳动和脚底漂移；不做非等比拉伸。
- `sleepy` 可以由无互动触发，但必须播放 `sleep` 循环，不得停在站立帧冻结；点击或拖动可唤醒。
- 移除绿色悬停圆环，保留轻淡的地面柔阴影。
- 聊天框只由点击猫打开；关闭后再次点击可重新打开。首次打开靠近猫，拖动后记住位置。

## 2. 当前证据与根因

### 2.1 点击与启动弹窗

`godot/scripts/roam_controller.gd` 已在短按时发出 `clicked`，`desktop/main.pyw::on_pet_event` 也会转成 `handle_action("chat")`。但 `main.pyw::main()` 在 Godot 模式下额外执行了 `QTimer.singleShot(900, ...)`，导致聊天框启动自动出现，掩盖点击链路的观感。

### 2.2 面板位置

`YayanController.place_panel()` 在 Godot 宠物窗口隐藏时固定把面板放在主屏左上，拖动位置没有写入状态文件。因此需要新增聊天面板位置的读取、保存、屏幕边界钳制和首次定位逻辑。

### 2.3 视觉尺寸变化

动画 PNG 都是 300×300 画布，但透明内容包围盒不同。例如 walk 帧内容高度约 214–247px，sleep 帧高度约 163–219px。节点统一 `scale` 并不能消除肉眼可见的逐帧尺寸变化；必须在运行时或资源构建阶段统一内容包络与脚底基线。

### 2.4 边界与冻结

当前 `Main.tscn` 使用 `scale=0.5`（约 150px），`roam_controller.gd` 使用 `SPRITE_SIZE=150`，而碰撞框仍为 180×200。`sleepy` 状态会把 `activity` 设为 `quiet`；`pet_sprite.gd` 又把 `quiet/fixed` 解释为 `speed_scale=0`，所以睡眠动画被错误冻结。

## 3. 实施阶段

### 阶段 A：只读基线与防回归

1. 再次确认 `git status`，不覆盖现有未提交改动。
2. 记录导出程序、窗口尺寸、动画资源和现有运行状态文件字段。
3. 为尺寸/边界/事件链路补充可重复的静态检查或 Godot 自检断言。

完成标准：修改前基线明确，现有聊天和 bridge 契约没有被改写。

### 阶段 B：Godot 视觉与交互

涉及：`godot/scenes/Main.tscn`、`godot/scripts/roam_controller.gd`、`godot/scripts/pet_sprite.gd`，必要时新增小型校准辅助脚本。

1. 把显示目标调整到约 240px（节点 `scale≈0.8`），并把视觉包络、点击热区、漫游边界统一到同一套尺寸常量；碰撞框改为与包络相符。
2. 使用保持比例的逐帧校准：按所有帧的透明内容包围盒计算统一目标包络，保持水平居中并对齐脚底基线；不做非等比拉伸。若现有帧仍有明显跳动，只补充必要的 walk/idle 过渡帧，不改变情绪语义。
3. 移除 `draw_arc` 圆环，保留低透明度椭圆阴影。
4. 修正睡眠状态机：`sleepy` 停止位置移动但不停止动画播放；点击、按下拖动或其它明确互动唤醒到 `idle`，重新选择漫游目标。
5. 保持拖动期间当前帧稳定；松手后恢复漫游。拖动的是猫节点，但由窗口控制器根据猫节点越过当前透明窗口安全边界的位移，移动整个 Godot 窗口，使窗口跟随猫，猫在新窗口区域继续活动。
6. 宠物窗口启动时仍由 `window_controller.gd` 放在当前屏幕右下；拖动后限制在当前屏幕可用区域，避免标题栏/任务栏之外。

完成标准：猫在所有状态下不明显逐帧缩放；睡眠动画可见且循环；拖动猫会带动透明窗口而非要求用户抓窗口；猫和阴影不切边。

### 阶段 C：Python 面板与持久化

涉及：`desktop/main.pyw`，必要时更新 `desktop/contracts.py` 或 `desktop/pet_bridge.py` 的事件字段，但不改变已有事件名称兼容性。

1. 删除 Godot 模式下 900ms 自动打开聊天的定时器。
2. 保留 `clicked -> handle_action("chat")`；面板已打开时只置顶/聚焦，不做闪烁式关闭。
3. 首次显示聊天框时，以 Godot 窗口屏幕坐标为锚点，优先放在猫旁边；没有可用宠物坐标时使用当前屏幕安全默认位置。
4. 给 `PanelDragFilter` 增加拖动结束保存；至少保存聊天面板位置和所属屏幕标识/坐标，恢复时做可用区域钳制。
5. 保存宠物透明窗口位置（建议沿用 `desktop-state.json`，增加版本兼容字段）；启动时恢复，恢复失败或越界则回退右下默认位置。
6. 不改变任务、专注、设置面板的业务流程；它们只复用安全的屏幕边界处理，不强制迁移到聊天框的持久化策略。

完成标准：启动不弹聊天；点猫打开，关掉后可再点开；聊天框靠近猫且拖动后跨重启恢复；宠物拖到左上后重启仍在合理位置。

### 阶段 D：构建与验证

1. 使用 `Godot_v4.7.2-stable_win64.exe/...console.exe --headless --path godot -- --self-check`，确认输出 `POC_OK`。
2. 如修改了 Godot 资源或导出脚本，重新生成/更新 `output/godot/YayanPet.exe`，不改变启动脚本的优先级。
3. 按顺序执行 `Stop-Yayan.cmd`、`Start-Yayan.cmd`；检查 `output/runtime/desktop-startup.log` 中 `godot-launch`、`pet-renderer`，确认使用 Godot 导出程序。
4. 人工验收：无绿圈；启动无聊天；点击可开关聊天；聊天靠近猫并记忆位置；默认右下漫游；拖到左上后窗口跟随且在新区域漫游；所有状态尺寸稳定；sleep 动画不冻结；全程不切边。
5. 运行针对性测试、语法检查和最终 `git diff`；不提交、不推送、不回退既有改动。

## 4. 主要风险与回退

- Windows 透明窗口移动与 Godot 节点坐标存在屏幕坐标/窗口坐标差异。先以单屏验证，再用当前屏幕可用矩形钳制；失败时保留现有窗口定位，不能影响聊天。
- 不同动画姿势的自然高矮差异不能被完全抹平。优先保持比例和脚底稳定，只有仍明显跳动时才补资源帧。
- 状态文件已有用户数据，新增字段必须向后兼容；解析失败只回退默认位置，不清空其它字段。
- 导出程序可能未同步脚本。验证时必须确认启动日志中的导出 exe 和 `POC_OK`，避免只验证源码目录。

# 专注、流式聊天与桌面交互设计

## 目标

在首次上传 GitHub 前，完善芽砚目前尚未闭环的桌面交互、专注陪伴和聊天响应功能。所有改动都必须保持芽砚温和、不施压的表达方式，尊重用户决定权，并维持现有隐私边界。

## 范围

本设计包括：

- 修复宠物文字气泡；
- 让右键操作菜单真正可用；
- 同一时间只运行一个由用户主动开启的专注会话；
- 支持选择时长、暂停、继续、提前结束、提醒和重启恢复；
- 专注结束后由用户自己记录成果；
- 为 Responses API 和兼容 Chat Completions 实现逐步显示回复；
- 支持停止等待、无内容超时、空响应处理、上下文限长和安全错误提示；
- 增加完全离线的单元测试与桌面集成验证。

本设计不包括：

- 保存聊天记录或实现长期记忆；
- 在用户没有主动开始专注时进行提醒；
- 制作新角色素材或分层角色动画；
- 连接真实模型、麦克风、语音识别或语音合成服务测试；
- 安装依赖、登录 GitHub、创建远程仓库或上传代码。

## 已确认的产品行为

### 宠物交互

- 左键点击宠物打开聊天窗口。
- 右键点击宠物打开操作菜单。
- 设置可以从操作菜单和聊天窗口标题栏进入。
- 操作菜单包括：聊聊、当前任务、陪我开始、安静一会、设置和退出芽砚。
- 在有第二套正式角色素材前，隐藏尚未生效的“换个样子”。
- 调用 `say()` 时显示宠物文字气泡，并在指定时间后隐藏。
- 每个新气泡都有自己的代次编号。旧气泡留下的计时器不能提前隐藏新气泡。

### 专注入口和控制

- 默认专注时长为 12 分钟。
- 提供 5、12、25、45 分钟快捷选项。
- 用户可以自定义 1–120 分钟。
- 专注面板显示当前任务、下一步、剩余时间和运行状态。
- 运行中的专注可以暂停、继续或提前结束。
- 关闭专注面板不会终止计时。
- 同一时间只允许一个专注会话。
- 已有专注时再次开始，必须先询问用户是否替换，不能静默叠加多个计时器。

### 专注结束与复盘

- 正常到时和提前结束都会进入简短复盘。
- 用户可以填写“刚才留下了什么”，并自行更新下一步和进度。
- 芽砚不推断用户是否成功，也不自动修改进度。
- 复盘文字和任务更新只保存在本机、已被 Git 忽略的运行状态中。

### 提醒力度

提醒只在用户主动开始的专注会话中生效。所有等级都会在专注结束时提醒一次。

| 等级 | 中途提醒行为 |
| --- | --- |
| 1 | 不进行中途提醒 |
| 2 | 进行到一半时轻提醒一次 |
| 3 | 进行到一半和剩余 2 分钟时各提醒一次 |
| 4 | 每完成四分之一阶段提醒一次，结束节点除外 |
| 5 | 每 5 分钟提醒一次；短于 15 分钟的专注最多进行两次中途提醒 |

已经触发过的提醒节点会写入专注状态，避免暂停、延迟回调或程序重启后重复提醒。

安静模式会抑制中途提醒、随机走动和非必要气泡，但不会抑制专注结束提示。只有用户已经开启“回复时播放语音”时，专注提醒才会尝试播放声音；语音失败不能改变专注状态。

### 程序重启后的恢复

- 活跃专注保存到 `output/runtime/focus-session.json`。
- 运行状态保存预计结束时间；暂停状态保存剩余时长。
- 重启时，如果预计结束时间尚未到达，询问用户是否继续。
- 如果预计结束时间已经过去，只显示“上次专注已经结束”的安静文字提示，不自动播放声音。
- 用户拒绝恢复时，安全结束旧会话，不替用户生成复盘结果。

## 架构

采用“适度拆分”，不继续把所有逻辑塞进 `desktop/main.pyw`，也不进行大范围界面重构。

### `desktop/focus_session.py`

保存与界面无关的专注状态和计时规则：

- 空闲、运行、暂停和完成状态；
- 总时长、剩余时间、开始时间和预计结束时间；
- 暂停、继续、提前结束和自然到期；
- 计算提醒节点并防止重复；
- 转换为可保存的 JSON 数据；
- 安全处理损坏或过期的本地状态。

该模块不导入 PyQt、不播放声音、不显示窗口，也不直接写文件，以便用模拟时间稳定测试。

### `desktop/chat_stream.py`

保存与模型供应商和界面无关的聊天辅助逻辑：

- 统一的新增文本片段格式；
- 从常见流式事件中提取文字；
- 裁剪最近消息；
- 判断完全空响应；
- 使用请求代次识别过期结果。

该模块不创建网络客户端，也不创建界面组件。

### `desktop/llm_client.py`

模型适配层继续负责与供应商通信，并为两种接口提供相同的流式回调方式：

- Chat Completions 的文本增量到达后立即转换；
- Responses API 的输出文本增量转换成相同格式；
- 每次收到事件时检查是否已取消；
- 连续 60 秒没有收到新内容时视为无内容超时；
- 不在用户可见错误中包含 API 密钥、认证头或完整供应商响应；
- 完全没有文字的响应用自然语言提示用户重试。

取消采用协作方式：停止接收新片段并忽略迟到结果，不强行终止 Python 线程。每次请求都有编号，已取消的旧请求不能覆盖后来的新请求。

### `desktop/main.pyw`

主程序继续负责窗口和信号连接：

- 显示右键菜单并连接所有可见操作；
- 管理不会互相干扰的气泡生命周期；
- 显示专注控制、每秒更新、恢复询问和复盘窗口；
- 创建临时回复气泡并逐步追加模型文字；
- 切换“发送”和“停止等待”状态；
- 保存本机专注和任务状态。

不顺便重构其他窗口，也不改角色素材。

## 数据流

### 聊天

1. 用户发送纯文本。
2. 控制器把用户消息加入本次内存会话，并创建一个临时的芽砚回复气泡。
3. 工作线程请求 `YayanLLM` 输出统一的文本片段。
4. 每个片段连同请求编号发送回界面线程。
5. 聊天窗口把纯文本追加到同一个回复气泡。
6. 正常结束后，完整回复才进入对话上下文，并按用户设置选择是否朗读。
7. 用户停止、超时、空响应或供应商失败时，输入控件恢复可用，并显示安全、明确的状态。

聊天记录仍只存在内存中。每次请求最多保留最近 16 条消息，同时限制为 12,000 个字符；优先保留最新的完整问答，并始终保留用户当前发送的消息。

### 专注

1. 用户选择时长并开始专注。
2. 控制器创建一个 `FocusSession`，保存到本机，并启动每秒一次的界面刷新。
3. 每次刷新向状态对象获取剩余时间和刚刚到期的提醒节点。
4. 控制器按照安静模式决定是否显示中途提醒，并保存已经处理的节点。
5. 暂停、继续、替换、提前结束和自然到期都使用明确的状态转换。
6. 专注结束后打开复盘窗口；只有用户亲自填写的内容才会保存。

## 错误处理与隐私

- 损坏的专注状态会被忽略，并显示本地、非致命提示；不会上传，也不会拼入模型提示词。
- 写入状态时先写临时文件，再替换正式文件，降低写入中断造成损坏的风险。
- 用户停止请求后，已经收到的部分文字可以保留并标记为“已停止”，但不能作为完整回复进入后续模型上下文。
- 超时时保留已经收到的部分文字，并允许重试。
- 意外异常只显示安全类别，不显示凭据、请求头或完整响应内容。
- 离线测试继续启用禁止读取凭据的保护，并只使用模拟服务。
- 真实聊天、麦克风、语音识别和语音合成测试可能向供应商发送用户提供的内容，因此必须另行获得明确许可。

## 验证方案

### 单元测试

使用 Python 标准库 `unittest`，不增加测试依赖。

覆盖：

- 同一时间只有一个专注，以及显式替换；
- 12 分钟默认值和自定义时长边界；
- 暂停、继续时剩余时间正确；
- 提前结束和自然到期是不同的明确状态；
- 1–5 级提醒生成符合已批准规则；
- 延迟刷新或重启恢复后不重复提醒；
- 运行、暂停、过期、损坏状态和拒绝恢复；
- 两种 API 事件都转换成相同的文本片段；
- 最近消息不超过 16 条和 12,000 个字符；
- 始终保留当前用户消息；
- 过期请求编号不能更新界面；
- 空响应和取消具有安全状态。

### 桌面集成验证

扩展现有离线验证脚本，覆盖：

- 左键进入聊天，右键打开菜单；
- 所有可见菜单操作都有控制器处理路径；
- 菜单中没有“换个样子”；
- 连续气泡的隐藏计时器不会互相干扰；
- 专注面板控制和“关闭面板但继续计时”；
- 同一个临时回复气泡可以接收多个文本片段；
- 停止后恢复输入，并拒绝旧请求的迟到结果；
- 超时或供应商失败后不会让聊天窗口一直保持忙碌；
- 测试不读取凭据，也不连接网络。

### 最终本地检查

- 运行全部标准库单元测试；
- 在禁止读取凭据的条件下运行 `scripts/verify_desktop.py`；
- 只有另行获得许可后，才启动桌面应用进行本地视觉检查；
- 检查 `git diff` 和 `git diff --check`；
- 扫描变更文件中的个人绝对路径和常见密钥格式；
- 确认 `output/` 和 `docs/task_records/` 继续被忽略；
- 未经分别批准，不暂存、不提交、不创建远程、不上传。

## 验收标准

- 操作菜单及所有可见功能都能进入。
- 宠物文字气泡按指定时间显示，不发生旧计时器隐藏新气泡的问题。
- 用户可以选择、运行、暂停、继续、替换、恢复或结束一个专注会话。
- 五级提醒和安静模式符合已批准规则。
- 专注结束只记录用户亲自填写的成果和任务更新。
- 两种 API 都能把文字逐步追加到同一个回复气泡。
- 停止等待、无内容超时、空响应、迟到结果和供应商失败后，界面都能恢复使用。
- 本阶段不保存聊天记录。
- 离线验证无需凭据和网络即可通过。
- 私有运行状态、日志、录音、任务记录和凭据都不能成为 Git 候选文件。

## 主要风险及应对

- **供应商事件格式不同：** 把事件解析隔离到独立模块，并用模拟事件覆盖常见 Responses 和 Chat Completions 格式。
- **强行终止线程不安全：** 使用协作取消、无内容超时和迟到结果过滤，不调用强制终止。
- **专注期间系统时间发生变化：** 同一进程内使用单调时间计算；只有重启恢复使用墙上时钟的预计结束时间。
- **重复提醒：** 保存已发送节点，并让提醒处理具有幂等性，即同一节点执行多次也只提醒一次。
- **范围膨胀：** 长期记忆、真实服务测试、新素材和全面界面拆分继续留在本次实现范围外。

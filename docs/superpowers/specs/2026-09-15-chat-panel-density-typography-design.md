# 聊天与辅助面板的密度、字体和生成状态设计

## 目标

在不改变芽砚现有功能、数据和水彩视觉基调的前提下，提高聊天正文和辅助文字的阅读层级，减少无效留白，统一设置 / 任务 / 专注面板的控件密度，并修复发送后误显示“（已停止）”的问题。

## 已确认方向

- 信息密度采用“清晰阅读”方向：聊天正文 15px 左右，辅助文字 11–12px，消息区紧凑但保留呼吸感。
- 字体采用“双字体层级”：标题和芽砚品牌短文本使用 `Noto Serif SC SemiBold`；正文、消息、说明、输入框和控件使用 `Noto Sans SC`。
- 用户已查看本地浏览器字体对比并选择标题衬线 + 正文无衬线。
- 现有绿色 / 杏色配色、圆角气泡、桌面宠物素材和功能入口保持不变。

## 范围

### 包含

- 聊天窗口的字号、行高、气泡间距、上下留白和输入区高度调整。
- 设置、任务、专注、专注复盘面板统一标题、说明、字段、按钮的字体和间距 token。
- 给 PyQt 字体选择增加清晰的本机字体回退链，避免缺字或不可用字体导致异常回退。
- 把“发送”和“停止生成”拆成明确的交互状态，避免发送动作误触发取消。
- 为取消 / 完成 / 失败状态增加离线测试。

### 不包含

- 不改模型供应商、请求格式、上下文裁剪、语音能力或本地数据结构。
- 不新增长期记忆、聊天记录持久化或新的角色素材。
- 不安装字体、不联网下载字体；只使用已在本机可用的字体。
- 不重构无关的启动、IPC、宠物动画和专注业务逻辑。

## 视觉与排版规则

### 字体

| 层级 | 字体 | 目标字号 | 用途 |
| --- | --- | ---: | --- |
| Display | Noto Serif SC SemiBold，回退 Noto Serif SC / Microsoft YaHei UI | 17–20px | 聊天标题、面板标题、芽砚名称 |
| Body | Noto Sans SC Medium，回退 Microsoft YaHei UI / Microsoft YaHei / Segoe UI | 15px | 聊天正文、任务内容、表单值 |
| Supporting | Noto Sans SC，回退 Microsoft YaHei UI / Microsoft YaHei / Segoe UI | 11–12px | 说话人、时间、说明、状态 |
| Control | Noto Sans SC Medium，回退 Microsoft YaHei UI / Microsoft YaHei / Segoe UI | 12–13px | 输入框、按钮、快捷选项 |

标题使用衬线体的范围严格限制在短文本，正文和控件不混用衬线体，以确保中文长段落、数字和输入体验稳定。

### 聊天窗口

- 聊天壳体内部边距保持约 16–18px；消息区上下边距约 10px。
- 气泡正文 15px、行高约 1.5；气泡间距约 9–10px。
- 说话人和时间使用 11–12px，颜色层级明显低于正文。
- 输入区高度约 40px；发送按钮和停止按钮共用高度、圆角和字重。
- 聊天窗口随尺寸自适应，但不再把字号压缩到难读的 9–10px。

### 辅助面板

- 标题行、说明行、字段行和操作行使用固定的间距阶梯，不依赖大块 stretch 产生布局。
- 字段高度和按钮高度统一；主按钮、次按钮和安静按钮仅通过颜色 / 边框区分。
- 面板尺寸只做必要收紧；信息不足时保留少量底部呼吸区，不让内容漂浮在大面积空白中。

## 生成状态修正

当前只有 `cancel_chat()` 和 `worker_cancelled()` 会追加“（已停止）”。发送按钮在忙碌时切换为“停止等待”，这会让普通发送动作和取消动作共用一个入口，造成误触和状态歧义。

改为：

1. 发送按钮始终发送；忙碌期间禁用发送动作，不清空或覆盖正在生成的回复。
2. 忙碌期间显示独立的“停止生成”按钮；只有该按钮触发 `cancel_requested`。
3. 停止按钮只在当前存在活动聊天工作线程时可用；取消完成后立即隐藏并恢复发送。
4. 正常完成进入完成路径；供应商异常进入错误路径；只有用户明确点击停止且线程报告取消，才追加“（已停止）”。
5. 迟到的旧线程结果继续被忽略，不得覆盖新消息或重新切换忙碌状态。

## 组件与数据流

### `desktop/main.pyw`

- 增加集中式字体常量 / 创建函数和界面字号 token。
- 更新 `ChatPanel` 的字体、间距、气泡和输入区布局。
- 在 `ChatPanel` 中拆分发送与停止控件，保持现有信号接口语义不变。
- 更新 SettingsPanel、TaskPanel、FocusPanel、FocusReviewPanel 的共用样式和布局间距。
- 保留现有 `WorkThread` 协作取消机制和控制器的线程生命周期。

### 状态流

```text
空闲 → 用户发送 → 生成中
生成中 → 正常完成 → 空闲
生成中 → 用户点击停止生成 → 已停止 → 空闲
生成中 → 供应商失败 / 空响应 → 错误 → 空闲
```

“已停止”和“错误”都是一次性消息状态；都不能进入后续模型上下文。正常完成才加入 `self.messages`。

## 错误处理与兼容性

- 字体按本机已确认的 Noto / Microsoft / Segoe 回退链创建，不要求额外安装。
- 如果 Noto Serif SC 不可用，标题退回 Microsoft YaHei UI，不阻塞启动。
- 取消仍使用协作事件，不强制终止线程。
- 面板内容超出可视区域时继续依赖现有滚动 / 自适应机制，不改变窗口功能。

## 验证方案

### 自动化

- 运行现有 `tests/test_chat_stream.py` 和 `tests/test_focus_session.py`。
- 增加纯 Python 的聊天状态测试：发送时不触发取消、停止按钮只在活动线程可用、取消状态不会进入上下文。
- 使用 `python -m py_compile desktop/main.pyw` 验证语法。
- 运行 `git diff --check`，确认无空白错误。

### 本地视觉检查

- 启动桌面预览或现有离线截图流程，检查聊天窗口的正文 / 辅助层级、单屏消息承载量和输入区高度。
- 依次打开设置、任务、专注、专注复盘面板，检查标题、说明、输入和按钮是否共享同一密度节奏。
- 在不连接真实模型的情况下，通过模拟忙碌 / 停止状态确认不会自动出现“（已停止）”。

## 验收标准

- 聊天正文清楚可读，辅助文字明显降级但不至于过小。
- 消息区上下留白收紧，单屏有效内容多于现状。
- 设置、任务、专注和复盘面板不再出现大面积无效空白，控件密度统一。
- 标题衬线体与正文无衬线体搭配稳定，中文不缺字。
- 普通发送不会显示“（已停止）”；只有用户点击“停止生成”才显示该状态。
- 正常完成、失败和取消均能恢复输入，并通过离线测试。
